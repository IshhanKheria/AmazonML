# Project initialization

## Authority and instruction order

1. The user's competition objective and explicit constraints.
2. The supplied `Problem Statement.txt`.
3. The local `AGENT.md` mission and operating rules.
4. The local `SKILLS.md` technical playbook.

The original challenge bundle is treated as read-only. Generated work belongs only in the working directories created alongside it.

## Initialized agent roles

- Lead ML engineer: scope, architecture, integration, and final approval.
- Dataset forensics: schema, dimensions, missingness, duplicates, countries, text characteristics, and ground-truth cardinality.
- Inventory/reproducibility: challenge files, utilities, templates, metadata, and package layout.
- Compliance/evaluation: output contract, fair-play, licensing, leakage controls, open-set behavior, and risk register.

## Skills activated for initialization

- Dataset Forensics
- Entity Resolution Fundamentals
- Open-Set Country Handling
- Submission Engineering
- Reproducible ML Engineering
- License / Fair-Play Compliance

## Skills deliberately deferred

Text Normalization, String Similarity, Address Resolution, Blocking, Pairwise ML Classification, Hard Negative Mining, Validation Design, Threshold Optimization, Error Analysis, and Competition Optimization will be activated only after the initialization audit and planning gate. No final model is trained during initialization.
